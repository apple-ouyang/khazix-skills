# Spec 与任务书 · 结构规格

以开源版任务书的结构为基线。Spec 是领导审核的决策合同，不是执行计划；整份 ≤4000 字符，单任务通常 1500–2000 字符。本规格不配样文——照规格自己写，措辞贴合当下任务，别套现成句式。

## 开头

- Spec front matter 保留 `review_status: draft | approved`：创建和重大合同修订时为 `draft`，只有领导明确批准且 Terra `PASS` 后才改为 `approved`。
- 这活为什么干：一句意图，说明为什么干，以及干完后世界是什么样。
- 两个要求打架时的让步顺序，例如「算得对 > 做得全 > 做得快」。
- 「只允许」「不许」是死规矩；「建议」只是情报，执行者有更好的路可以走。

## 领导已经拍板

逐行记录领导明确提出或逐项确认的决定。措辞整理不是新决定，不要混入下一节。

## 我替领导拍的板（待确认）

没问出口、但会改变结果、风险或验收的决定逐行写：问题 → 推荐默认值（标「猜的」）｜猜错代价。没有待确认项也保留本节并写「无」；不能靠删除标题掩盖是否存在代拟决定。

写不出机器可判命令的目标（文风、体验类）也放这里：改成抽查点＋领导亲验，并注明只能半托。

## 范围与非目标

- 范围：允许改变的业务能力、模块、数据或外部行为。
- 非目标：明确保持不变的内容，以及最诱人的顺手活。
- 边界：判卷标准、不可逆操作、权限、花费和外部 mutation 等不能越过的线。

不要列实现者打开仓库就能找到的文件、函数或逐文件白名单；真正影响用户授权的写入范围和副作用边界必须写。

## 现状与任务 0

- 实测数字逐条带来源与日期，查不到的标「猜的，没验证」；能提前实证的关键结论写进来。
- 任务 0 只写开工前必须核对的前提与失败边界。命令、完整基线证据和恢复点在批准后进入临时 `PROGRESS.md`，不让领导审核操作清单。

## 任务 N

这里只列领导需要审核的业务结果：一句话目标、可观察验收和失败后果。它不是执行任务节点；完整任务拆分、依赖边、逐文件步骤、`write ownership`、worker、branch/worktree、focused verification、RED/GREEN 和 reviewer 调度都在执行开始后的 `PROGRESS.md` 展开。

## 执行分组（多任务时）

- 先串行：必须先锁定的共享前提或合同，并说明原因。
- 可并行：互不依赖的结果组；只写结果，不写 worker 数和 lane 名。
- 最后串行：统一集成、迁移或综合验收。

领导批准的是结果级并发关系。实际并发数仍由执行者按真实依赖和写入冲突决定。

## 规矩

- 防作弊点名到具体姿势：skip/todo、放宽判断、把被测对象换成假的、删测试、改阈值或验收脚本、`|| true` 都算失败；测试数／覆盖率不得低于基线。
- 不新增未获批准的流程、权限、依赖、schema、外部 mutation 或不可逆操作。
- 同一条验收连败 3 次换下一项；结果比开工差就如实阻断。「没做成但说清了」合格，「做了但更糟」不合格。
- 项目自有纪律（分支、PR、提交前检查）继续生效，但不复制进 Spec。

## 完成条件

- 两条硬指标：一条度量领导要的结果，不写工作量；一条证明范围、安全边界和非回归成立。
- 每条必须有实际、可复现的证据；只说做完了不算。
- 写明止损：或已跑满 N 轮，满轮即停，如实汇报卡在哪、还差什么。

## 执行期 PROGRESS

用户批准、Terra `PASS` 且明确继续后，在唯一 integration worktree 创建 `tmp/<task-slug>/PROGRESS.md`。它承接开源版原来用于断点续跑的执行细节：完整 Task DAG、依赖、状态、文件 ownership、lane/commit/review/verification、阻塞摘要和恢复点。

普通失败、重试和可自行修复的问题只写 PROGRESS。只有确实需要领导拍板或外部协助、agent 无法自行推进时，才按需创建同目录 `BLOCKED.md`。PROGRESS 保留任务的 `blocked` 状态、摘要和 blocker ID；BLOCKED 按 ID 写完整原因、证据、已尝试方案、影响范围和所需协助，不复制任务状态，也不预建空文件。

PROGRESS 不提交到 `main`。未合入、验证失败、存在阻塞或仍有恢复点时保留；BLOCKED 有未解决项时不得完成。阻塞解决后更新 PROGRESS，重大裁决同步回 Spec，BLOCKED 无未解决项即可删除；只有 `merge-main` 成功、post-merge verification 通过且无未解决项时自动删除 PROGRESS。

## 探索型：改四处，其余同款

领导要的是答案本身（调研、选型、「该不该做 X」）时：

1. 完成条件换成学习目标：结论设上限，每条附来源与日期或可复跑步骤。
2. 预算换成可承受损失：最多花多少时间、查多少来源，耗尽就交「目前最优＋还没排除什么」。
3. 防作弊主防编造：凑数结论、查无此文的引用、没跑过的「实测」都算失败。
4. 此路不通也可合格交付：用原始证据说明死因。
